# MVU 转台账（测试版 0.1.1）

将 MVU 角色卡变量转换成瑟瑟台账表格，由台账存储和填表，兼容桥向卡内状态栏提供 stat_data。

基于 **[wmdl2/mvu2shujuku](https://github.com/wmdl2/mvu2shujuku)** 0.8.3 修改。原作者/项目维护者：wmdl2；原版权：mvu2shujuku contributors。台账适配：yuan-1992-png。非官方测试版，未获原作者或台账作者背书。

## 支持范围

- 已用 **瑟瑟台账 V1.147 实际存储代码**完成隔离验证。状态栏 V4.000、小手机 V1.300 为核对到的环境版本，没有进行它们的完整回归。
- 生成新的“_台账”角色卡、专用模板及 MVU 读写桥；不在转换阶段修改原卡。
- 专用模板名为“MVU台账-角色名模板”，仅绑定转换卡，不改全局默认预设。
- **仅用于新聊天**，不迁移已有台账、数据库或旧 MVU 聊天。
- 不支持 ERA、含 $ 私有变量的卡、VWD 动态说明和填表规则中的动态 EJS；检测后停止转换。
- 没有调用付费模型，不承诺真实填表准确率或缓存收益。

## 安装

这是 **SillyTavern 第三方扩展**，不是酒馆助手 JSON。仍需自行安装瑟瑟台账及卡片需要的酒馆助手。

本版位于现有仓库独立的 **mvu-ledger 分支**。默认 main 是另一个“台账缓存布局”扩展，**不要把已经安装的缓存扩展切换到本分支**。

在 SillyTavern/data/<用户名>/extensions/ 目录打开终端：

```sh
git clone --branch mvu-ledger --single-branch https://github.com/yuan-1992-png/ST-Ledger-Cache-Layout.git ST-MVU-Ledger-Bridge
```

或下载 [分支 ZIP](https://github.com/yuan-1992-png/ST-Ledger-Cache-Layout/archive/refs/heads/mvu-ledger.zip)，解压为同级独立文件夹 ST-MVU-Ledger-Bridge，确保 manifest.json 直接在其中。ZIP 安装需手动更新。

刷新酒馆，在扩展面板打开“MVU转台账 · 测试版”。不要同时用原转换器处理同一张卡。

## 使用

1. 备份原卡，选择卡片或 PNG/JSON 文件转换。
2. 先查看警告，不要删规则绕过不支持的结构检测。
3. 如果使用小手机等依赖原台账的功能，在“合并其他数据库表格”中选择所需的原台账预设，加载并勾选所需表，再点击“合并到转换结果”。0.1.1 会保留这些表的分组、频率和注入设置，把 MVU 变量表放在后面；不带入来源聊天记录。
4. 下载结果或点击“保存角色卡和模板”。新卡默认带“_台账”后缀。保存可能为新卡另存关联世界书，按日志核对名称。
5. 用转换卡新建聊天并等待台账加载。桥只在空的新聊天初始化，拒绝覆盖已有记录。
6. 核对初始变量，再测试一轮能明确核对的变化，例如物品数量 2→1，同时查看台账、状态栏与历史。

合并后使用新卡的专用完整模板，不要再用原 18 表模板覆盖它，也不要只导入合并 JSON 却继续使用内置旧模板的卡。旧版转换结果须重新转换、合并和保存。若同名预设存在但内容不同，使用新的卡名另存，不能覆盖已有聊天。

**0.1.1 修复的是表结构共存，不是重叠字段自动同步。** 两边对同一人物状态仍可能填出不同结果；原 Schema 对台账自动填表的完整校验也未完成。先用新聊天验证，不把本版当作完整联动已经实现。详见 [18 表基础方案](docs/LEDGER-FOUNDATION.md)。缓存布局扩展对动态表的适配需另行验证。

写入通过台账持久化接口提交。加载未完成、聊天切换、保存失败或表结构不符会报错。写入使用完整快照，复杂卡可能开销较大。

停用前备份聊天与台账。原卡和普通台账不依赖本扩展，但转换卡依赖桥接器，停用后其状态栏不能保证继续运行。
