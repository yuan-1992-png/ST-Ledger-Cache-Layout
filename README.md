# 台账填表缓存适配

为 SillyTavern 的瑟瑟台账填表请求调整排列：将同一条消息中的固定表规则集中放在前面，将变化的已有数据放在后面，帮助支持前缀缓存的 DeepSeek API 复用更多输入。

这是独立的酒馆第三方扩展，不是酒馆助手脚本，也不是台账本体。当前为 **0.2.1 测试版**，默认关闭，需要绑定角色。它不会额外请求 AI。

## 安装与启用

1. 酒馆 → 扩展 → 安装扩展，粘贴本仓库地址：
   ```text
   https://github.com/yuan-1992-png/ST-Ledger-Cache-Layout
   ```
2. 安装后刷新页面，打开扩展设置中的「台账填表缓存适配」。
3. 进入要使用的角色聊天，点击「绑定当前角色」。
4. 确认台账表结构与适配配置匹配，再勾选「启用适配」。
5. 正常对话触发填表后，查看面板是否显示「已重排并转交请求」，以及 API 实报缓存命中量。

手动安装时，把仓库文件放入 `SillyTavern/public/scripts/extensions/third-party/ST-Ledger-Cache-Layout/`，使 `manifest.json` 位于该目录第一层。操作的是运行酒馆的电脑或服务器；在手机或 Mac 上访问远程酒馆，不需要分别安装。

如果以前安装过「源源版」或另一份同名适配扩展，请先禁用重复副本再刷新。重复包装不会叠加生效。

## 两种预设，导入位置不同

| 文件 | 导入位置 | 用途 |
| --- | --- | --- |
| [ledger-template.json](presets/ledger-template.json) | 台账自身的表格／模板导入功能 | 18 张表的结构、规则、分组和世界书注入配置；不含任何人物行或纪要 |
| [cache-profile.json](presets/cache-profile.json) | 本扩展的「导入缓存适配配置」 | 校验填表任务签名、10 张角色表的规则、表头及顺序 |

内置适配配置与 `cache-profile.json` 相同。角色组每楼更新，基础组每楼更新，不更新组的频率为 0；**只优化角色组的 10 张表**。基础组包含随状态变化的规则，保留原请求。

建议先在新聊天中使用附带台账模板。套用模板会使用其表结构、更新频率及世界书注入设置；它不是旧聊天的数据迁移工具。已有聊天请先用台账自身的导出功能备份，确认自己的字段与分组需要保留哪些，再决定是否套用。

模板来源于用户现用台账模板的无数据导出，保留原表格规则及本地真名归并等修订；本仓库不包含台账、状态栏或小手机的完整脚本。需要先自行安装这些原项目。

## 从 0.2.0 升级

0.2.1 的附带模板补充了人物同一性、跨表姓名校验和重复关系防护。改名被列为独立更新条件；日记与纪要继续保护历史原文。表数、分组、频率、读取方式及世界书注入位置保持原样。固定规则增加约 2,158 字符，角色组有 9 张表的指纹变化。

- 已使用新模板：在本扩展点击「恢复内置适配配置」，核对后重新启用，或者导入新版 cache-profile.json。
- 继续使用旧模板：导入 [旧版适配配置](presets/legacy/cache-profile-0.2.0.json)。[旧版台账模板](presets/legacy/ledger-template-0.2.0.json)也保留供核对。
- 若此前导入过自定义配置，更新扩展不会覆盖它；需自行选择对应版本。
- 不匹配的配置会跳过优化，不会强行重排。首次使用新规则的缓存表现可能变化，仍以 API 用量为准。

**导入模板不等于修复既有数据。** 已有旧称、重复人物／关系需要单独核验；模板约束不能替代确定性的跨表改名程序。本次版本不包含任何用户的姓名纠错数据或聊天。

## 为什么安装后可能没有重排

本扩展不会猜测未知请求的结构。以下条件均需匹配：

- 当前角色已绑定，并且开关启用。
- 模型名称包含 `deepseek`。
- 使用支持的请求入口：酒馆 Chat Completion，或柏宝库的 `save-generate`。
- 前三条 system 消息的任务签名匹配。
- 台账块唯一，角色组每张表的名称、顺序、表头、固定规则及分隔符匹配。

不满足时保留原请求。不同的状态栏全局前后置提示词、自定义填表说明、修改过的表规则，都可能造成不匹配。**导入相同台账模板不代表任务提示词也相同。**

如果表结构相同，仅任务说明不同，可在本机使用 [适配说明](ADAPTATION.md) 中的离线校准工具生成新配置。工具不会上传请求文件；不要把带正文和密钥的原始请求上传到仓库或 Issue。

## 效果与限制

普通排列通常为：规则 A → 数据 A → 规则 B → 数据 B。

重排后为：规则 A → 规则 B → 数据 A → 数据 B，并增加表名和编号对应说明。

原规则、数据及 row_id 均保留，仅改变一个台账消息的内部排列。不改变正文历史数量、角色、其他消息、模型参数或表格分组。对应标记会少量增加输入字符。

缓存是前缀复用。如果台账块之前的世界书或其他消息先变化，后方固定规则仍可能无法命中；本扩展不解决整个正文请求的排列问题。也不压缩历史、不删除记忆、不修复加载慢、不自动纠正已有台账数据。

**不能保证命中率，也不能保证模型填表准确率不变。** 既有小样本对照曾出现细节改写差异。发布前检查了结构完整性、请求只发送一次、异常回退和界面行为；这些检查不能替代实际模型的长期验证。请同时观察填表结果与费用。

## 诊断、关闭与卸载

面板分别显示台账块的前缀字符相似度，以及 API 返回的缓存 Token 数据。字符相似度不是实际计费指标；API 不返回 usage 时会显示不可获取。

诊断导出只含结构统计、处理原因、模型名和用量，不含提示词、聊天正文、人物行、API 密钥或 API 地址。扩展内的诊断和用于比较的最近台账块仅保留在当前页面内存，刷新后清除。绑定角色和适配配置保存于酒馆扩展设置。

取消勾选后，后续请求恢复原排列。禁用／卸载后刷新页面即可移除请求包装；已经发出的请求不会撤回。扩展不写台账数据文件，也不写世界书。

## 兼容与开发

- 当前配置针对台账 V1.130 / V1.131 的指定角色组；V1.131 已通过旧数据重放与请求结构比对。
- 状态栏 V3.937 的本地组合已检查；不代表所有第三方配置均兼容。
- 官方版本、模板或提示词更新后，校验不匹配会跳过；需重新检查并适配。
- 项目是社区适配工具，与原台账、状态栏、SillyTavern 或 DeepSeek 官方无隶属关系。

需要 Node.js 22 或更新版本运行测试：

```sh
npm test
```

代码、测试和说明见本仓库。测试只使用合成数据，不需要 API 密钥，也不会调用模型。
