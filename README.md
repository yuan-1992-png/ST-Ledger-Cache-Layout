# 台账填表缓存适配：通用格式预览版

版本：0.3.0-format-preview，2026-10-25。

本版本基于 yuan-1992-png 的 ST-Ledger-Cache-Layout 本地源码制作。上游地址：https://github.com/yuan-1992-png/ST-Ledger-Cache-Layout 。通用预览版使用独立分支 `generic-format-preview`；主分支继续保留原版。

## 适配范围

只处理经过配置核对的一个 10 表分组。在原有的一条 system 填表消息内，将固定表规则集中放在前方，已有数据放在后方，并添加表名及编号对应说明。保持规则原文、表头、row_id、数据原文、消息角色和其他请求参数。

| 来源 | 处理范围 |
| --- | --- |
| 纯文字卡 | 使用台账原生十表请求时可匹配 |
| MVU 卡与台账同时使用 | 匹配台账十表请求；原生 MVU 更新请求原样发送 |
| MVU 经数据桥接入台账 | 仅匹配所选十表；额外变量表若混入同组，则整个请求跳过 |
| JSON、嵌套对象、数组、中文、转义换行 | 若已作为台账文本字段发送，则原文保留，不解析或重写变量 |
| 多模态消息、工具调用、不符合格式的请求 | 跳过重排 |
| 普通正文、纪要融合、其他分组 | 不在本配置的适配范围 |

插件不负责 MVU 与台账之间的同步，也不解决两个系统共同维护同一状态造成的冲突。支持当前的 DeepSeek 命名模型筛选、普通 Chat Completion 和柏宝库 save-generate 外层请求。

## 包内内容

- `manifest.json`、`index.js`、`core.mjs` 等：酒馆扩展。
- `tools/build-profile.mjs`：使用原生 v2 模板及两份请求核对结构，输出哈希配置。
- `examples/`：完全虚构、非色情的十表模板与两份请求样例。
- `tests/`：中性自动测试。
- `VALIDATION.json`：验证范围与限制。

预览版没有内置任何个人角色、聊天或适配白名单，默认关闭。它不会自动读取聊天学习规则，也不会自动信任第一次捕获的请求。

## 离线试用

在本目录运行：

```sh
node --test tests/format.test.mjs
node tools/build-profile.mjs examples/template.json examples/request-text.json examples/request-mvu.json examples/generated-profile.json
```

输出文件已存在时不会覆盖。使用自己的非色情测试场景时，提供原生 schemaVersion=2 的台账模板，以及两轮已有数据不同、任务签名相同的请求。可在命令末尾指定分组编号，默认 1；所选组必须恰好 10 表。

工具核对模板原文与请求中的固定规则，并验证表顺序、名称、表头、分隔符和任务签名。输出只包含结构及哈希，不包含行数据或提示词正文。结构通过不代表提示词语义已经人工审核，也不证明填表准确率不受排列变化影响。

## 扩展安装与配置

这是扩展文件包，不是酒馆助手脚本 JSON。将本文件夹放进酒馆用户的 `extensions` 目录，也可在扩展目录执行以下命令安装指定分支：

```sh
git clone --branch generic-format-preview https://github.com/yuan-1992-png/ST-Ledger-Cache-Layout.git
```

先停用旧版/重复的填表缓存适配扩展，再重新打开酒馆。不要同时运行两个填表重排器。

在“台账填表缓存适配 · 通用格式预览”设置中导入核对后的配置，再绑定测试角色并手动启用。导入、恢复默认和重新绑定均会关闭优化。关闭开关后，下一次请求恢复原排列；已发出的请求不会撤回。

这里导入的是缓存匹配配置，不会覆盖台账模板、角色卡、世界书、正则或聊天。使用独立设置键 `yuanLedgerCacheLayoutFormatPreview`，不会迁移或覆盖旧扩展配置。

## 更新与限制

新增了通过明确模板和两轮样例生成十表匹配配置的工具，取消预览包对特定个人模板的依赖。规则或表结构变化仍会跳过，不能只修改角色名就绕过校验。含动态宏的规则需要单独审核。

仅使用中性数据完成离线格式、真实台账组装函数和浏览器设置面板测试。未用个人聊天进行配置，未调用真实 AI。安装不代表已导入或启用个人配置。

测试证明的是请求结构和数据片段保留。模型仍可能因排列变化产生不同输出；输入中较早变化的其他消息也会限制缓存收益。诊断的前缀字符数不是缓存 Token 数，收益需看 API 实报用量，不能保证命中率。

原始请求可能包含私人数据或凭据。仅在本机处理，不要把请求、聊天、台账快照或 settings.json 上传到公开仓库。
